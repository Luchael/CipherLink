# GameTodo Auto Sync v0.5.0 — 서버 회차 / 자동 체크 규칙

## 1. 무엇이 변경되었나요?

Todoist의 반복 작업은 완료 순간 '다음 날짜'로 이동할 수 있습니다. 게임 데이터의 회차는 **자정이 아니라 해당 게임의 서버 초기화**를 기준으로 합니다. 그래서 서버 초기화 전에 이전 회차 정보를 읽고 완료하면 오늘 새로 시작할 반복 작업이 건너뛰어질 수 있습니다.

이 문제를 방지하기 위해 다음 6개 조건을 전부 만족해야 자동 완료합니다.

1. 해당 게임의 **한국/아시아 서버 초기화 시간이 확인**되었음.
2. 현재 시각은 **오늘의 게임 초기화 시각 이후**임. 일일·주간·OCR 반복 작업 모두 적용.
3. 초기화 직후 **20분(설정 가능) 유예 시간**이 지남.
4. 해당 게임/콘텐츠의 현재 점수가 명확한 최대 점수에 도달함.
5. **Todoist 작업의 시작일(마감일로 등록한 due 날짜)이 한국 시간 기준 오늘 또는 과거**이며, 같은 게임의 동일한 제목을 갖는 미완료 작업이 **정확히 하나** 있음. due가 없으면 자동 체크하지 않음.
6. 서버가 응답 생성 시각을 제공한 경우(KuroBBS `serverTime` 등), 그 시각이 **오늘 게임 초기화 이후**인지 추가 검증합니다.
7. 같은 계정·회차·콘텐츠의 완료 증거를 **최소 2분 간격으로 두 번** 확인하고, 그 회차의 완료 기록이 아직 없음.

Todoist에 `item_close`를 보낸 후에는 SQLite에 해당 회차 ID를 저장하고, 다음 동기화부터 해당 회차에 다시 완료 명령을 보내지 않습니다. PC/안드로이드가 별도 DB를 쓰더라도 Todoist에 전송하는 명령 UUID는 동일 작업·회차에서 같으므로 API 재전송에 의한 중복 실행을 줄입니다. **두 기기의 시계를 자동 동기화/검증하는 서버 기능이나 원자적 분산 락은 없으므로, 완벽한 동시성 보장을 뜻하지는 않습니다.**

## 2. 시간 예시: 원신 아시아 서버

| 한국 시각 | 완료 감지 |
|---|---|
| 10월 28일 03:00 | **금지.** 오늘 오전 5시 게임 초기화 전, 어제 4/4 기록이 남아도 닫지 않음 |
| 10월 28일 05:05 | **보류.** 초기화 직후 캐시 유예 구간 |
| 10월 28일 05:25 | 4/4 첫 관측 → 증거 1개 저장. 여전히 완료 전송 없음 |
| 10월 28일 05:45 | 같은 회차 4/4 두 번째 관측 → Todoist 작업의 due가 10/28 또는 그 이전일 때만 완료 |
| 완료 이후 | Todoist가 due를 10/29로 옮긴 경우, `due > 10/28`라서 재완료 금지 |

예시의 05:25/05:45는 조회 주기 20분을 가정한 것이고, 반드시 그 시각에 호출된다는 의미는 아닙니다.

## 4. 스크린샷의 기존 Todoist 목록에서 어떤 항목을 감지하나요?

| 기존 제목 | 상태 | 실제 근거/제약 |
|---|---|---|
| `[원신] 일퀘` | 구현 | HoYoLAB 일일 의뢰 현재/최대치 |
| `[열차] 일퀘` | 구현 | HoYoLAB 일일 훈련 현재/최대치 |
| `[젠존제] 일퀘` | 구현 | HoYoLAB 일일 활약 현재/최대치 |
| `[명조] 일퀘` | 구현 | KuroBBS 일일 활약 현재/최대치 |
| `[엔필] 일퀘` | 구현 | SKPORT 일일 활약 현재/최대치 |
| `[명방] 일퀘` | 조건부 | ArkPRTS가 일일 임무의 current/max **둘 다** 제공해야 함. 그렇지 않으면 무시 |
| `[젠존제] 주간퀘` | **추가 구현** | HoYoLAB `weekly_task` 점수가 최대치인 경우, 월요일 05:00 회차 기준 |
| `[명조] 탑` | **추가 구현** | KuroBBS `towerData`의 목표치 달성 + 서버의 **미래 갱신 시각**이 있을 때만 순환 회차로 완료 |
| `[열차] 주간퀘스트` | **아직 자동 체크하지 않음** | HoYoLAB `rogue`는 모의우주 포인트이지 이 작업 전체와 일치한다는 근거가 없음 |
| `[원신] 주간보스` | 무시 | 할인 사용 횟수와 Todoist의 하위 작업 완료 조건이 일치하지 않음 |
| `[명조] 주간퀘` | 무시 | KuroBBS `weeklyData`는 전투 콘텐츠(주간 보스) 정보. 일반 주간퀘와 동일하다고 단정하지 않음 |
| `[림컴] 거던`, `[명방] 섬멸작전 1800개` | 무시 | 계정 완료 데이터 확인 불가 |
| `[원신] 지지전/나선`, `[젠존제] 시유방어전·강습전`, `[열차] 혼돈·허구·종말`, 기타 엔드콘텐츠 | 무시 | 대응하는 현재 회차의 검증 가능한 점수·시각이 없어 추측 완료 금지 |

**계정 상태 조회 어댑터가 코딩되어 있음과 실제 계정에서 성공적으로 데이터가 반환되는 것은 별개입니다.** 마지막 단계에는 실제 계정의 응답을 확인해야 합니다. 자동 완료가 되지 않는 항목은 조용히 무시합니다.

## 5. 내가 직접 다른 항목을 연결하려면

`gametodo/task_rules.py`의 `AUTO_BINDINGS`가 **기본 설정**입니다. 예시:

```python
Binding("zzz", "[젠존제] 주간퀘", "weekly", "weekly_task")
Binding("wuthering", "[명조] 탑", "rotation", "tower")
```

- 두 번째 값: Todoist의 **정확한 작업 제목**
- 세 번째 값: `daily`, `weekly`, `rotation` (순환 시 다음 갱신 타임스탬프 필요)
- 네 번째 값: `gametodo/live_data.py`가 실제로 반환하는 점수의 이름

코드를 건드리지 않고 `config.json`에 추가할 수도 있습니다:

```json
"account_data": {
  "custom_bindings": [
    {
      "game": "hsr",
      "title": "[열차] 모의우주 주간 포인트",
      "kind": "weekly",
      "metric": "rogue_weekly"
    }
  ]
}
```

위 예시로 `[열차] 주간퀘스트`를 자동 연결하지 않았다는 점에 유의하세요. **기존 [열차] 주간퀘스트가 모의우주만을 의미하지 않기 때문**입니다. 실제로 의미가 같은 경우에만 직접 매핑하세요.

KuroBBS에서 확인한 `weekly_boss`, `weekly_rogue`, `tower`, `slash_tower` 등도 `metrics`에 저장합니다. 하지만 **하나의 점수**가 **Todoist 전체 작업 완료**와 정확히 일치할 때만 연결해야 합니다.

## 6. 시각 설정 바꾸기

`config.json`의 `account_data` 안에 아래 항목을 추가할 수 있습니다:

```json
"reset_times_kst": {
  "genshin": "05:00",
  "hsr": "05:00",
  "zzz": "05:00",
  "wuthering": "05:00",
  "endfield": "05:00",
  "limbus": "06:00"
},
"weekly_reset_weekdays": {
  "limbus": 3
},
"reset_grace_minutes": 20
```

`weekly_reset_weekdays`: 월요일 = `0`, 화요일 = `1`, ... 일요일 = `6`.

**기존 `reset_hours_kst`도 작동하며, `reset_times_kst` 값이 있으면 우선**합니다. 기존 `config.json`은 업데이트 시 지우지 마세요.

## 7. 점검 명령어

기기별 설치된 Python에서 프로젝트 폴더 내에서 실행:

```bash
python -m gametodo schedule-status
python -m gametodo accounts-status
python -m unittest discover -s tests -q
```

- `schedule-status`: **로그인 없이** 오늘 서버 초기화 여부·현재 일일/주간 회차 출력.
- `accounts-status`: **Todoist를 수정하지 않고** 인증된 게임 진행도 진단. 인증정보가 없으면 실패할 수 있음.
- 테스트: 네트워크 없이 날짜·중복·점수·주간/엔드콘텐츠 판정을 검사.

## 8. PC·Android 설계

- Windows: 기존 Python CLI를 사용합니다.
- Android: 기존 Kotlin 플로팅 앱(게임 실행 감지) + Termux에서 Python 계정/동기화 엔진 실행. UI와 동기화 엔진을 분리해 화면 캡처를 계속 돌리지 않습니다.
- 동일한 언어를 강요할 이유는 없습니다. 완전한 Kotlin 단독 자동 동기화 엔진은 **이번 패키지에는 없습니다**. Termux 실행이 Android 절전 설정에 의해 중단되면 다음 실행 시 동기화를 재개합니다.

## 9. 안전 관련

- 모든 완료는 점수형 조건으로, 실제 보상 수령을 따로 검증하지 않습니다(사용자 지정 정책).
- 스크린 OCR의 '작업' 감지에도 회차·예정일 제약이 적용됩니다. 이벤트 자체는 종료일이 마감일이므로 사전에 보상을 수령하면 종료 전에도 수동/화면 신호에 의해 완료할 수 있습니다.
- 프로세스가 여러 기기에서 동시에 실행되는 경우 Todoist 명령 UUID와 로컬 기록으로 중복을 완화하지만 네트워크 지연·시계 불일치까지 완전히 방지하지는 못합니다.
- 비공식 계정 데이터 API는 계정/게임사 정책을 확인한 뒤 사용하세요.
