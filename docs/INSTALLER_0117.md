# 0.11.7 GitHub 다운로드·Windows 설치판

사용자 요청: GitHub에서 바로 설치 파일을 받기, 제거 기능, 이미 설치돼 있으면 업데이트.

기존 Windows EXE는 무설치 실행 파일이어서 Windows의 설치·제거 등록이 없었다. 앱 소스는 0.11.6이었지만 Windows 파일 리소스는 0.11.5.0에 남아 있었다. Windows 파일 속성으로 버전을 비교하는 업데이트 도구가 이를 구별할 수 없으므로 0.11.7에서 일치시켰고 앞으로 불일치하면 빌드를 중단한다.

## 구현

- `pc/installer/CipherLink.iss`: 한국어 Inno Setup 설치판. 고정 AppId, 현재 사용자 설치, 기존 설치 위치 재사용, 시작 메뉴·선택 바탕화면 바로 가기, Windows 설치된 앱 제거와 `unins000.exe`. 낮은 버전 설치 거부.
- `tools/build_windows_installer.ps1`: EXE ProductVersion 일치 검사, 설치 파일·SHA256 생성.
- `tools/test_windows_installer.ps1`: 이전 설치→업그레이드→다운그레이드 거부→제거→재설치. 기본 데이터와 다른 무설치판 시작 항목은 보존하고 자신의 시작 항목만 정리한다.
- `.github/workflows/release.yml`: 실제 Windows 설치 수명주기 검사 후 설치 파일을 초안에 첨부한다. 앱 소스는 버전 태그에 고정하고, 패키징 도구는 해당 워크플로 실행의 정확한 커밋에 별도로 고정해 두 이력을 재현 가능하게 남긴다.
- `tools/update_download_links.py`: 실제 첨부파일만 README에 연결, 초안 로그인 안내, 미업로드 APK 안내. 오래된 CI가 최신 다운로드를 덮지 않도록 버전 검사. GitHub 원문 README SHA를 사용해 다른 수정 덮어쓰기 방지.
- `tools/release_metadata.py`: 소스/Windows 파일 리소스 버전 일치 검사, 설치 파일의 체크섬도 릴리스 메타데이터에 포함.

설치·업데이트·제거가 `~/.gametodo`의 기존 계정·설정·DB를 삭제하지 않는다. 설치판이 다른 위치의 모든 무설치 파일을 자동 검색·삭제하거나 사용자 비밀정보를 복사하지 않는다. 무설치 EXE만 있던 사용자는 설치판을 한 번 실행하면 설치 관리가 시작된다. 원래 무설치 파일은 별도로 남는다.

## 배포 제약

현재 소스 저장소는 공개지만 바이너리는 소유자만 보는 초안으로 둔다. GitHub 관리 API와 비공개 다운로드 저장소 생성 API는 403을 반환했다. APK 업로드도 환경의 `uploads.github.com` 차단으로 실패했다. 허용 항목은 환경 설정 초안에 이미 저장했으며 실제 적용은 환경 설정 저장·게시가 필요하다. 실제 APK가 첨부되기 전에는 README에 작동하지 않는 APK 다운로드 링크를 만들지 않는다.

## 검증

PC 전체 286개 통과. 다운로드 파일 존재·URL·이전 버전 덮어쓰기 방지, EXE 리소스 버전 불일치, 비공개 배포 조건 회귀를 포함한다. Windows CI 결과는 릴리스 실행 기록과 함께 확인하며 사용자 PC의 실제 로그인·실계정·기존 커스텀 데이터와 Android17 설치는 별도 미검증이다. APK는 버전 정보만 변경했으며 기존 서명/패키지를 유지한다.
