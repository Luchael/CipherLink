# 0.11.5 진행도·가챠 정리

2026-10-29 KST. 테스트·공개 구현 확인과 실제 계정 검증을 구별한다.

## 재현된 PC 원인과 수정

`PYTHONPATH=pc python -m unittest pc.tests.test_progress_contract_0114 -v`에서 원신 보스, 젠존제 주간 일정, 시유 SDK 응답, 합산 게이지 숨김 등 최초 5개 검사가 모두 실패했다. 수정 후 원본 시나리오를 포함해 통과했다.

확인한 구현은 [PyPI genshin 1.7.31](https://pypi.org/project/genshin/1.7.31/)의 배포 휠이다. 아래 파일을 직접 대조했다.

- `models/genshin/chronicle/notes.py`: `remaining_resin_discounts/max_resin_discounts` 모델 속성과 원본 `remain_resin_discount_num/resin_discount_num_limit`의 별칭 관계. PC는 원본 키만 읽고 있어 SDK 객체에서 주간 보스 값이 누락됐다. 두 형태를 모두 읽도록 수정했다.
- `models/zzz/chronicle/notes.py`: 실제 주간 일정은 `weekly_task.cur_point/max_point`. PC의 예전 `current/max` 경로에 실제 키를 추가했다.
- `client/components/chronicle/zzz.py`: `get_shiyu_defense(raw=True)`는 `hadal_ver`와 바깥 `hadal_info_v2`를 제거한 내용을 반환한다. 제4·5전선 필드를 가진 이 평탄한 형태를 파싱하도록 수정했다. 단순 점수 합계로 S 달성을 추정하는 규칙은 추가하지 않았다.
- `client/components/base.py`: SDK가 원본 Unix 시각을 `{timestamp, tzinfo}`로 감싼다. 이 경우에도 실제 시즌 시작·종료 시각을 보존한다.
- PC 실시간 메모 요청은 `return_raw_data=True`, `autoauth=False`, `lang=ko-kr`로 받아 미지원 모델 필드가 사라지는 문제를 줄인다. SDK의 기록 공개 설정 변경은 실행하지 않는다. 원본과 SDK 객체 양쪽의 파싱 회귀를 유지한다.

## 화면과 완료 판정

- PC·Android 원신/스타레일의 보스 제목은 **주간 보스**로 통일했다. 표시 값은 **사용한 주간 보상 횟수 0/3 → 3/3**이며, 잔여 횟수 감소와 게이지 증가가 반대로 보이던 문제를 정리했다. API가 증명하는 것은 보상 사용 횟수이며 실제 전투 승리 횟수와 구별한다.
- 스타레일·젠존제의 합산 `weekly` 2/2 게이지는 화면에서 숨겼다. 내부 자동 완료 조건은 그대로 사용한다.
- 스타레일은 **통합 18000점 + 주간 보스 보상 3/3 사용**을 내부에서 판정한다.
- 젠존제의 **리두 주간 일정**은 실제 점수/전체 상한을 표시하고, 주간 보상 기준 800점을 별도로 안내한다. 합산 주간 목표와 같은 값이 아니므로 두 게이지를 중복 표시하지 않는다.
- 현상금 의뢰의 **횟수**와 **8000점**은 다른 단위다. 실제 포인트 필드가 없으면 횟수로 8000점을 만들어 자동 완료하지 않는다. 실제 제공되는 횟수·포인트만 표시한다.
- 시유 방어전과 위험한 강습전은 등급/별 게이지 아래에 실제 방별·보스별 점수를 작은 문구로 표시한다. 절망 점수는 일반 강습전 완료 판정에 합치지 않는다.
- PC의 시유/강습전 조회가 실패해도 항목 자체를 숨기지 않고 `정보 없음`과 안전한 실패 이유를 표시한다. 점수 0과 조회 실패를 구별한다.

## 엔드필드

사용자가 추가한 정확한 제목 **`[엔필] 주간퀘스트`**를 PC·Android 공유 연결표에 추가했다. `weeklyMission.score/total`이 실제 제공되고 목표에 도달하면 한 번의 유효한 관측으로 완료한다. 반복은 사용자가 확인한 **매주 월요일, 7일 주기**다. 현재 앱의 KST 05:00 초기화 설정과 20분 유예, 현재 회차·예정일·공유 UUID 중복 방지를 그대로 유지한다. 초기화 시각 자체를 새 공식 자료로 검증했다는 뜻은 아니다.

공유 카탈로그는 총 **36개**, 자동 16/조건부 3/수동 17개다. 기존 제목은 바꾸지 않고 새로운 항목 한 개만 추가했다. 지난주/향후 회차 예정일·낮은 점수·다른 제목·월요일 초기화 전/직후를 완료하지 않는 회귀 테스트를 추가했다.

기존 카드 상세 응답에 `indieHard.indieHardGroups`가 실제로 있으면 **그림자 이정표**의 일반/고난도 클리어 수와 현재 운영 시작·종료 시각을 표시한다. 현재 기간, 올바른 숫자 시각, 모든 스테이지의 실제 Boolean `isPass`가 있어야 게이지를 만든다. API에 필드가 없으면 표시를 만들지 않는다. 기간 길이는 실제 시작/종료의 차이이며 고정 반복 주기로 간주하지 않는다. 이 도전은 읽기 전용으로만 추가했고 Todoist 자동 완료 규칙은 추가하지 않았다.

**위기 협약**의 한국어 이름과 공개 모델도 확인했지만, 별도 글로벌 API 경로와 반복 일수·완료 목표가 확인되지 않아 호출/자동 체크를 추가하지 않았다. 더 긴 기간의 콘텐츠도 같은 원칙으로 조사했다. [출처·지역·주기 조사](RESEARCH_BANNERS_ENDFIELD_20261029.md)에 확인된 사실과 미확인 항목을 구분했다.

## 가챠 라벨과 출처

신규 자동 가챠 작업에는 게임 라벨과 **`가챠`**를 함께 붙인다. 기존 자동 가챠도 다음 수집 시 새 라벨을 보완하며 사용자 라벨을 보존한다. 일반 수동 작업을 제목만으로 덮어쓰지 않는다. 생성 UUID는 유지해 PC·Android 중복 생성을 막고, Android 수정 UUID는 실제 수정 내용의 해시를 포함해 이전 수정 명령이 새 라벨 반영을 막지 않게 했다. `가챠` 라벨은 새 게임 등록 후보에서 제외한다.

다른 출처 조사 결과:

- **스텔라 소라 KR:** 이미 수집 어댑터가 있다. 이번 최신 재조회는 403이었으며 최신 수집 성공으로 보고하지 않았다.
- **명일방주 KR:** 갱신되는 공개 게임 데이터에서 기간과 한글 캐릭터 ID를 확인했다. 선택 가능한 목록과 확정 픽업을 구별해야 하며 새 어댑터는 아직 연결하지 않았다.
- **림버스:** 제작사 Steam 뉴스와 PickupCal 경로를 확인했다. 공식 공지의 영상 의존, 일정 중복과 철자 차이로 인해 파서 범위만 넓혀 임의 등록하지 않았다.
- **리버스 KR:** 조사한 자료만으로는 한국 서버 기간을 확정하지 못했다.

## 문서와 배포

README에서 작동하지 않는 최신 릴리스 링크, 중복 인수인계 설명을 제거하고 실제 기능·설치·개발·검증 범위로 줄였다. 앱 설정의 미게시 GitHub 최신 버전 버튼도 제거하고 현재 버전과 파일 교체 방법만 남겼다. 사용자 허용에 따라 AGENTS.md의 작업 범위를 연관 버그·사용성·안정성 개선까지 확장했다.

GitHub 관리 권한과 네트워크 설정을 제품 사용의 필수 조건으로 두지 않는다. 설치 파일은 이 대화로 제공하며 새 공개 릴리스를 게시하지 않는다. `uploads.github.com`은 설정 초안에 이미 추가했지만 현재 실행 환경 허용 목록에는 아직 없다. 적용은 환경 설정에서 저장·게시해야 하며 휴대폰 설정과는 별개다.
