# 0.11.6 엔드필드 반복 콘텐츠와 시작 프로그램 상태

2026-10-29 KST. [0.11.5 수정](PROGRESS_0115.md)을 포함한다. 이 문서의 구현 상태가 이전 조사 문서의 후보 설명보다 최신이다.

## 사용자 확정 규칙

| 기존 Todoist 제목 | 유지하는 반복 | 완료 기준 |
| --- | --- | --- |
| `[엔필] 주간퀘스트` | 매주 월요일 | 카드 `weeklyMission.score/total` 달성 |
| `[엔필] 그림자 이정표` | 49일 | 실제 최신 시리즈의 일반·고난도 전부 클리어 |
| `[엔필] 위기 협약` | **21주 = 147일** | 세 종류 임무 목표와 도금 훈장 확인, 또는 실제 플레이 종료 시각 이후 |
| `[엔필] 전쟁의 메아리` | 매주 | 실제 현재 주차의 일반·고난도·극난도 및 추가 목표 전부 완료 |

위기 협약은 사용자가 설명한 **3버전 × 7주** 고정 반복을 유지한다. 초기 버전 간격이 달랐던 과거 자료로 이 설정을 바꾸지 않는다. ToDoGames / N일의 기존 `[엔필] 위기 협약`만 연결한다. 새 작업 생성, 반복 문자열 변경 및 날짜 변경은 하지 않는다.

## 원인·검증·변경 파일

엔드필드 카드는 일일/주간만 읽었고 장기 콘텐츠 연결이 없었다. 공개 EndUID의 실제 경로·타입과 공식 공지/클라이언트 데이터를 대조했다. `activityEndTs`는 그림자 이정표 본체의 영구 도전 종료가 아니라 부가 이벤트의 종료일일 수 있고, 전쟁의 메아리의 시즌 합계는 현재 주차와 다르다. 필드 누락을 완료로 만들거나 시즌 합계로 주간 작업을 닫지 않는 모의 응답 테스트로 검증했다.

- PC `endfield_longterm.py`, `fixed_cycles.py`, `account_sources.py`, `account_watch.py`, `skport.py`, `live_data.py`; Android `EndfieldLongTerm.kt`, `FixedIntervals.kt`, `AccountProviders.kt`, `AccountSync.kt`, `EndfieldNotes.kt`.
- 공유 연결표 `todoist_bindings.json` 총 39개: 자동 19 / 조건부 3 / 수동 17. 한국어 정확한 제목과 기존 호환 키를 유지한다.
- 글로벌 SKPORT의 읽기 전용 후보 `card/indie-hard`, `card/crisis-contract`, `card/war-echoes`를 같은 인증 세션으로 시도한다. 중국 계정 서버로 대체하지 않는다. detail에 그림자 이정표가 있으면 추가 호출하지 않는다.
- **글로벌 Asia 실응답은 미검증**이다. 실패·필드 누락·현재 회차 확인 불가 시 완료를 보류하고 일일/주간 조회는 유지한다. 실패한 추가 경로는 1시간 뒤 재시도한다. 로그인 확인 중에는 이 추가 조회를 생략한다.
- 그림자 이정표는 실제 최신 개방 시각과 Boolean 클리어 필드를 사용한다. 부가 이벤트가 끝났어도 본체 기록은 표시하며 가짜 본체 종료일을 만들지 않는다.
- 위기 협약은 유효한 `gameplayEndAtTs`가 있으면 그 플레이 종료를 사용하고, 없을 때 `endAtTs`를 사용한다. 종료 시각은 반드시 실제 API 값으로 확인한다. Android에는 이벤트 ID·기간만 저장하며 점수/계정 원문이나 인증정보를 이 캐시에 저장하지 않는다. PC는 실행 중 메모리 캐시를 사용한다.
- 전쟁의 메아리는 유일한 현재 주차 `startTs/endTs`를 선택한다. 경계 주차가 정확히 7일이 아니어도 실제 기간을 사용한다. 목표 별 수를 추정하지 않는다.
- 초기화 유예·Todoist 현재 예정일·반복 간격·회차를 모두 확인하며, 과거 완료 기록으로 다음 반복을 자동 체크하지 않는다. 확인된 API 개방 시각이 Todoist 현재 예정일~다음 예정일 범위에 속하지 않으면 보류한다. 미래 예정일을 앞당겨 완료하지 않는다.
- PC와 Android의 완료 명령은 같은 API 회차 문자열을 사용한다. 유효한 목표를 한 번 확인하면 즉시 체크하고, Android 성공 알림을 유지한다.

PC 시작 프로그램은 등록/해제 결과를 활동 기록에서만 확인할 수 있었다. `startup.py`로 현재 사용자 Run 등록과 실제 실행 경로, Windows 사용 안 함 상태를 조회하도록 분리했다. `gui.py` 설정 화면에 상태·새로고침·Windows 시작 앱 설정 열기를 추가하고 등록/해제 뒤 읽어 확인한다. 현재 경로로 재등록하면서 소유한 구 버전 항목만 정리하며 다른 앱 항목은 보존한다. 관리자 권한을 요구하지 않는다. 작업 결과와 오류도 현재 화면 상단·하단에 즉시 표시한다.

## 검증과 미검증

- PC 전체 회귀 **282개 통과**. 실제 응답 형태, 실패 시 일일 유지, 현재 주차/시리즈, 고정 반복, 첫 관측 1회 완료, 잘못된 프로젝트/섹션 차단, 시작 프로그램 레지스트리 모의 검사를 포함한다.
- Kotlin 전체 회귀 **25개 프로그램 통과**. Android APK 빌드 성공. 기존 0.11.5와 패키지·서명 일치 및 versionCode **33 → 34** 증가 검사 통과.
- Tkinter 합성 데이터로 진행도·설정 화면을 열어 상태와 즉시 피드백을 확인했다. 실제 Windows 레지스트리/자동 부팅 실행, Windows EXE 실행, Android17 설치·계정 API·알림은 **미검증**이다.
- 새 파일은 기존 성공한 별도 설치판과 같은 Android 패키지/서명을 사용한다. 원본 0.10.2에 덮어쓰는 파일과는 구별한다. 앱 데이터 삭제나 삭제 후 재설치를 요구하지 않는다.
- GitHub 공개 릴리스를 게시하지 않는다. 앱 사용에 GitHub 연동은 필요 없다.

실기기 확인은 시작 프로그램 설정의 등록→해제 상태 변화와 앱 상단 안내, 엔드필드 진행도에서 실제 수치/기간이 나타나는지 보면 된다. 실패 시 게임명·앱 버전·안전한 오류 문구만 공유한다. 비밀번호·쿠키·토큰·인증 URL은 공유하지 않는다.
